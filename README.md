# 서버시간 PiP (iOS)

티켓팅·수강신청용 서버시간을 밀리초 단위로 측정해 **PiP(화면 속 화면)** 로 다른 앱 위에 띄워두는 시계 앱입니다.

## 기능

| 기능 | 내용 |
| --- | --- |
| 서버시간 측정 | 대상 사이트 서버에 직접 여러 번 요청해 `Date` 헤더의 초 경계를 좁혀 밀리초 단위로 측정 |
| 팝업(PiP) 타이머 | 다른 앱 위에 서버시계. '팝업 타이머' 버튼으로만 시작. ◀◀/▶▶ 로 설정 단위만큼 미세 조정 |
| PiP 자동 닫기 | 시작 옵션에서 HH:mm:ss 지정 → 서버시간이 그 시각이 되면 자동으로 닫힘 (백그라운드 포함) |
| PiP 크기 | 기본 16:9 / 긴 막대 L·M / 얇은 막대 / 초슬림 / 정사각형, PiP 중에도 즉시 변경 |
| 측정 근거 | 추정 오차(±ms)·사용 샘플·마지막 측정, 자세히: RTT 산점도·패스별 결과·시간 경과 오차 |
| 서버별 차이 경고 | 패스마다 따로 잰 값이 오차보다 크게 벌어지면 '서버마다 시각이 다름' 경고 |
| 정확도 설정 | 낮음 / 보통 / 높음 / 매우 높음 / 커스텀 (샘플·반복·경계 보정) |
| 보정 | 반응속도, 네트워크 딜레이(왕복/2), PiP 버튼 조정값 — 합계를 '보정 +0.018초'로 표시 |
| 연습 | 55초에서 흘러가는 시계를 00.000초에 맞춰 5번 누르기 → 평균 반응속도를 시계에 반영 |
| 일정 | 오픈 시각 등록 → 카운트다운(앱·PiP), 5분·1분 전 알림, 오픈 전 한 번 자동 재측정(기본 1분 30초 전) |
| 타이머 효과 | 정각 3초 전 비프 + 정각 긴 비프(매 분 / 일정 직전만), 정각 10초 전 빨간 표시 |
| 집중 화면 | 서버시계만 화면 가득 (가로 회전, 화면 꺼짐 방지) |
| 사이트 | 기본 티켓팅 사이트, 예매창 주소 직접 입력·저장(이름 바꾸기·순서 바꾸기·삭제), 최근 동기화 |
| 기타 | 첫 실행 사용법, 한국어 오류 안내·오프라인 처리, 버전·빌드 번호 표시, 다크/라이트 모드 |

## IPA 받기

GitHub Actions 의 **Build IPA** 워크플로를 수동 실행하면 테스트 → 빌드 후 서명 없는 IPA 가
[Releases › latest](https://github.com/horridalex/pipservertime/releases/tag/latest) 에 올라갑니다.
AltStore / SideStore / Sideloadly 로 본인 Apple ID 서명 후 설치하세요.
빌드 번호는 워크플로 실행 번호이며 앱의 설정 › 정보에 표시됩니다.

## 직접 빌드

Xcode 프로젝트는 [XcodeGen](https://github.com/yonaskolb/XcodeGen) 으로 생성합니다.

```bash
brew install xcodegen
xcodegen
open PipServerTime.xcodeproj
```

Signing & Capabilities 에서 Team 을 고르고 실기기에서 실행합니다 (iOS 16+).
PiP 를 위해 Info.plist 에 `UIBackgroundModes = audio` 가 설정되어 있습니다.

## 측정 원리 (`Sync/DirectServerTimeSource.swift`)

서버 응답의 `Date` 헤더는 1초 단위입니다. 요청이 실제로 나간 시각 t0, 응답 첫 바이트가 온 시각 t1
(둘 다 `URLSessionTaskMetrics`), 헤더 시각 D 로부터 `D − t1 ≤ 오프셋 < D + 1 − t0` 이고,
여러 샘플의 범위를 겹쳐 오프셋을 좁힙니다.

한 패스:
1. 샘플 N개를 0~10ms 무작위 간격으로 보냄 (서버의 1초 안 여러 위치에 고르게 떨어지도록)
2. 왕복이 느린 샘플 제외 (최소 RTT 의 1.5배, 최소 +15ms 초과)
3. 경계 보정: 지금까지의 합의 구간으로 다음 초 경계를 예측해, 그 앞뒤에 시차를 둔 샘플을 동시에 보냄 (넓게 → 좁게)

샘플은 패스를 거치며 누적되고, 최종값 = 전체 샘플이 가장 많이 동의하는 구간의 중앙,
오차 = 그 구간 폭의 절반입니다. 합의에 못 든 샘플은 제외로 표시합니다.
리다이렉트는 따라가지 않습니다 (3xx 응답의 Date 도 유효, 왕복 1회만 측정).

오차의 하한은 대략 네트워크 왕복 시간의 절반입니다. 서버 시계가 잘 관리되는 Google·Apple 로
확인했을 때 측정값이 서로 20ms 안에서 일치했습니다.

참고: Cloudflare `/cdn-cgi/trace` 의 `ts=` 는 소수점 아래가 실제와 무작위로 어긋나 사용하지 않으며,
Cloudflare 를 쓰는 사이트는 Date 헤더도 초 경계가 정확하지 않아 오차가 크게 나올 수 있습니다.

## PiP (`PiP/`)

- `ClockFrameRenderer`: 줄 단위 레이아웃을 `CVPixelBuffer` 에 그려 `CMSampleBuffer` 로 변환
- `ClockFrameLoop`: GCD 타이머로 프레임 공급. 앱이 앞에 있거나 PiP 가 떠 있을 때만, 최대 30fps (초가 바뀌는 순간은 즉시)
- `PiPClockController`: `AVPictureInPictureController` 연결, 앞/뒤 버튼 = 미세 조정,
  자동 닫기(백그라운드에선 콘텐츠 소스 해제로 즉시 닫음), 닫힌 뒤 컨트롤러 재생성

## 디자인

- 앱 아이콘: 스톱워치 + PiP 창 (아이보리·잉크·민트) — 원본 `design/AppIcon-D1.svg`
- 테마(`Views/Theme.swift`): 라이트 = 아이보리 바탕·흰 카드·잉크, 다크 = 짙은 남색. 민트는 강조에만.
  시계 카드와 PiP 는 잉크 바탕에 아이보리 숫자, 소수점 아래만 민트.

## 한계

- 기본 사이트 목록이 실제 예매 처리 서버인지는 확인하지 않았습니다. 예매창 주소를 저장해 재는 것이 가장 정확합니다.
- 서버를 여러 대 쓰는 사이트는 서버마다 시각이 수십 ms 다를 수 있습니다 (앱이 경고 표시).
- 자동 재측정·카운트다운 소리는 앱이나 PiP 가 켜져 있을 때만 동작합니다.
